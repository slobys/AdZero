# 切换代理

v0.18.0 将外部期限的重载方式统一到 OpenClash、Nikki、SSR Plus+ 与无代理时的系统 DNS，缺少既有依赖时提前停止应用。概览的「代理接入」可展开区分已识别插件和实际接入。PassWall／PassWall 2、OpenClash／Nikki 的共用内核按所属配置目录核对，服务记录缺失时不再单靠保存的开关猜测；已确认停止与归属不明分别处理。不会在恢复时重新启动用户已停止的插件。

v0.15.6 保留 PassWall 原生 DNS 引擎，修正直接启动 DNS 进程时的 SIGCHLD 继承，并精确失效其屏蔽名单缓存。分流开关及 DNS 变更复用现有接入，成功时只重载一次。新增小型 `coreutils-timeout` 依赖：用外部 120 秒期限代替有问题的 ucode 内部超时，超时后另有五秒终止期限；PassWall 服务子进程使用标准 022 权限掩码，AdZero 私有文件仍保留原权限。缺工具时在应用前停止，安装器准备依赖失败时保留旧保护。

运行状态会分别核对 dnsmasq 直接屏蔽配置、ChinaDNS-NG 上游进程和 null 屏蔽组。发现 DNS 父进程 SIGCHLD 阻塞会报告 `degraded/dns_sigchld_blocked`，不会仅凭规则文件存在当作正常。重载仍有有限重试与退避，不反复重启整个网络。

这轮没有新增跨代理的过渡 DNS 服务器，也没有重建现场 nftset。保留原引擎和减少重复重载可减少不必要的切换，但原生服务重启仍有中断窗口；Windows 无需清缓存、完整 ChatGPT/Codex 使用和现场 nftset 错误必须分别实机验收。已有坏缓存不能由路由器远程撤销。

v0.15.5 修复交接检查对 PassWall 全局段的误判：与原生插件的 `@global[0]` 保持一致，只读取第一段；后面有空的全局段时不再整轮跳过，也不会选用后面另一个启用段来绕过第一段的关闭设置。不会删除、保存或提交用户的 PassWall 配置。

`dns-handoff status` 的跳过原因现在分别显示：`protection_disabled`（保护关闭）、`backend_disabled`（后端关闭）、`not_managed`（非 AdZero 管理）、`paused`（临时暂停）、`passwall_unconfigured`（没有默认全局段）、`passwall_disabled`（第一段未启用）、`dns_redirect_disabled`（默认 DNS 接管未启用）、`acl_unsupported`（启用了自定义 ACL）和 `config_unavailable`（配置读取失败）。`unsupported_context` 仍表示原生进程、监听或规则不满足处理条件。首页已接入 PassWall 时会说明对应原因；其他代理正常运行时，不把 PassWall 关闭当作故障。

如果命令行与交接检查读到不同的开关值，请保持当前代理不切换，对照同一时刻的输出。隔离环境的基础配置、增量修改与运行覆盖配置对照一致，不能据此替真实设备确定差异原因。不要为排查而删除配置段、清理增量或强制提交设置。

v0.15.4 增加独立的 DNS 会话交接检查。用户提供的现场证据显示：旧 UDP 源端口仍沿用切换前的 NAT 绑定，走原始系统 DNS；新源端口已走 PassWall。仅刷新页面不能修复这个路径问题。

保护开启时，每五秒检查 PassWall 默认 DNS 进程、UDP/TCP 监听和原生 DNS 重定向规则。入口连续两次稳定，且确认唯一活动代理为 PassWall 后，只移除 LAN 客户端发往路由器 53 端口、回复端口仍与当前入口不同的旧 IPv4 UDP DNS 绑定。下一次查询会重新进入当前规则，无需关闭原客户端 UDP 套接字。正常 DNS、外网 DNS、非默认连接区域和其他业务连接均不清理，不改防火墙规则。

这项检查独立于耗时较长的规则同步，不持有其操作锁。存在自定义 ACL、未知原生规则、多个代理、监听未就绪或依赖缺失时会跳过。它不会把“已修复旧连接”标记成完整网络验收，也不会清除电脑／浏览器已缓存的坏答案；这些记录需等待过期，必要时在修复路径后清理一次。现有原始 DNS 上游和各插件 DNS 设置仍需确保可靠，切换期间及 IPv6 不在本轮修复保证范围内。

安装包新增小型 `conntrack` 依赖。你的 APK 固件如果第三方源仍异常，可先用 `apk add conntrack` 准备依赖，再运行升级器；安装器准备软件源失败时会保留旧版保护，不要为了升级关闭代理或删除恢复记录。检查状态使用 `/usr/libexec/adzero/dns-handoff status`；`repaired` 为本检查进程修复的旧会话数，进程重启后重新计数，不是广告数量。`conntrack_missing` 表示缺工具，`unsupported_context` 表示当前 DNS／ACL 方式不满足保守处理条件。

隔离验收：官方 OpenWrt 25.12.5 的 dnsmasq-full 2.93、nftables、conntrack 1.4.8 与生产交接代码，两个独立网络空间复现旧绑定、自动移除旧绑定和同一 UDP 套接字转入新入口；保留正确 DNS 与其他 UDP 会话。dnsmasq 以普通用户运行，并核对新 TCP DNS 查询。活动插件与 LAN ubus 信息为明确的测试替身，未连接或修改实际路由器。该结果不等于修复了现场独立的 nftset、TCP 阻塞或权限报错。

AdZero 自动接入 NaiLink、PassWall、OpenClash、Nikki，并提供 SSR Plus+ 原生广告过滤接入。先停止旧代理，再启动新代理，最后在 AdZero 点击「重新检测」。保护开启时，后台也会定期核对变化，通常在一分钟内尝试同步。

v0.15.3 区分“后台仍在切换”和“切换失败”。后台操作持锁且进程身份核对通过时，显示“正在同步代理接入”，暂时不提交关闭、重新加载或应用；完成后自动更新页面。不会再把正在恢复旧插件的中间状态直接当成需要人工关闭的故障。页面可见时每五个轮询周期核对一次，活动操作最多核对六十次，超时仍可手动重新检测；不会抢锁、杀进程或删除锁。

如果恰好在同步开始前点击关闭，仍可能遇到锁竞争。锁等待超时表示**这次关闭没有执行**，页面会显示“上次关闭未执行”，下面显示实际保护状态，不自动重试关闭。同步完成后若仍需要关闭，再点击一次即可；点击“重新检测”可清除旧操作提示。真实恢复错误继续保留恢复入口。锁目录存在但进程已退出、身份不符、记录缺失或过旧时，不会伪装成仍在同步。

先开新代理、再关旧代理的短暂重叠期间，仍不会从两个活动代理中随意选择一个。只保留一个代理后，后台会再次核对；如果不能恢复旧插件的配置，仍保留恢复记录。本次不改变代理选择、DNS 或分流规则。

NaiLink 的管理服务可以一直运行，而代理内核已经停止。AdZero 查询实际内核状态，不再仅凭管理进程或保存的启用选项判定它正在代理。PassWall 不要求必须注册 procd 实例；其原生配置归属与服务记录会一起核对。共享的 Xray、Mihomo 进程不会随意归给某个插件。

NaiLink 0.6.74 的 `coreStatus` 中，`running` 是可能省略的持久化切换字段，`runtime: ready` 也可能只是管理器已就绪。AdZero 经同一认证接口核对 `/health/ready` 的当前内核、配置及数据面状态，再确认运行或停止；不直接把缺少 `running` 当成运行。接口拒绝、切换中、API-only、字段异常或内核不一致时保持无法确认；sing-box／mihomo 仍需匹配归属明确的实际进程。此兼容修复经隔离测试，不代表已在反馈者路由器验收。

如果提示多个代理，会列出识别到的插件；如果查询失败，会提示无法确认内核状态，而不是误报为同时运行。只需检查对应插件后重新检测，切勿删除恢复记录。

切换时会先恢复旧插件中 AdZero 管理的设置，再接入新插件。已确认停止的旧代理不会被重新拉起。若旧插件的管理接口完全不可用，恢复可能仍需先让该接口可访问；AdZero 会保留记录并说明失败，不会丢弃原设置。

PassWall 2、HomeProxy 目前仅识别。SSR Plus+ 接入原生 `/etc/ssrplus/deny.list`，保留节点、DNS 上游和分流策略；使用它时请先关闭 AdZero 自动分流。恢复只移除 AdZero 标记块，保留原有列表和后来添加的用户域名。

SSR Plus+ 的活动判断检查其自有客户端进程路径或配置参数，不把保存的节点选择、DNS 辅助程序、服务端或其他插件的共享 Xray 进程当成它正在代理。

v0.14.0 修正 rc.common 启动脚本的调用方式。PassWall 和 SSR Plus+ 会进一步核对实际 DNS 进程、配置包含路径及三个规则样本；尚未加载时最多立即重试一次，失败后间隔至少五分钟，连续三批仍失败则等待人工重新加载。手动重新加载或改变规则可重新尝试，不强制下载全部订阅。已停止的旧代理不会被拉起。

这些检查确认配置链路，实际 LAN、IPv6 网络、用户 ACL、加密 DNS 绕过和节点出口仍需设备验收。不同插件的原生接口分别适配，不根据共享内核猜测插件所有者。

v0.15.2 修复“点击关闭并恢复后仍提示未完成，刷新页面却已经关闭”的状态确认缺口。任务成功后若读到恢复中的状态，会先做四次间隔一秒的复查；仍未确认时提示继续核对。页面可见时每五个轮询周期检查一次主状态，恢复异常最多检查十二次，之后停止自动检查并保留“重新检测”。检测到统计快照中的接入已经变化或保护已停止，也会核对主状态。

上述自动确认只读取状态，不重复关闭、启用或重载。确认期间主开关显示“正在确认”，防止重复提交，仍可点击“重新检测”；自动确认超时后恢复手动操作入口。确认已关闭后即可再次开启，无需刷新整页；任务明确报错、状态最终与请求不一致或恢复持续失败时仍会提示错误。隐藏页面暂停轮询，离页后丢弃迟到回复；旧的后台回复不会覆盖较新的手动检测结果或缓存。切换事务本身仍按原有逻辑恢复旧插件并接入新插件，不丢弃恢复记录。

本轮隔离测试覆盖管理服务运行但内核关闭、切换 PassWall、真实多代理冲突、API 无法访问、恢复时不启动旧代理，以及开关自动分流的两种切换路径。实际路由器的切换仍需现场确认。

v0.13.0 的首页接入卡片跟随轻量统计快照更新，后台同步结束后会显示当前已接入的插件；检测到代理、配置已同步和终端检测通过仍是三个不同层次。拦截量不增长时先做终端查询对照，不把普通查询强行算为拦截。
