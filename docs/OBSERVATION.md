# 拦截统计与效果检测

v0.16.0 增加当前接入／配置采集周期的 DNS 应答耗时，随原统计每秒刷新：正常正应答、命中规则后的拦截应答分别计算平均值；另显示至少 500 ms 的正常慢应答和 15 秒内未观察到应答的数量。没有有效样本时显示横线。

耗时来自抓包时间，不受采集进程消息排队时间影响。清零、接入或配置变化及采集器重启后重新收集耗时样本，不沿用之前链路的均值。原累计拦截／请求数的保留规则不变。检测流量和重复包不加入耗时；时间回退或异常样本忽略。

这是可观察的局域网 A/AAAA 请求至应答耗时，包含路由器缓存，不包含客户端本地缓存或完整 TCP 握手；不能当作上游纯耗时或缓存命中率。未观察到应答也可能是采集遗漏，TCP 连接未建立时更不会凭空出现 DNS 查询计数。该功能不主动探测、不修改上游、缓存或代理。

## 首页怎么读

页面可见时，每秒自动读取统计快照，无需手动刷新。切到后台会暂停读取，返回时立即更新；不会为更新数字重新下载规则、读取完整运行状态或重载代理。首次挂载页面时保留 LuCI 的轮询注册，离开页面后自动清理。

- **已拦截 DNS 请求**：在当前主局域网接口观察到、命中当前有效规则，并且收到拦截应答的请求数。
- **已观察 DNS 请求**：保护开启、统计就绪期间观察到的 A / AAAA 查询数。
- **DNS请求拦截占比**：已拦截 ÷ 已观察请求；不代表网页广告拦截率，也不能把剩余比例当作漏掉的广告。
- **规则域名**：当前加载的规则数量，和请求次数分别显示。

一次网页访问可能发出多条 DNS 查询，一条查询也可能涉及多处广告或正常资源。因此请求数不等于广告横幅、弹窗或视频广告个数。A 与 AAAA 是不同查询，按各自请求计数。

v0.19.2 将上述说明直接放在统计卡片内。IPv6 回环地址 `::1` 与已有零地址、IPv4 回环地址一样作为阻断形式识别；截断应答中的地址不再作为“命中规则仍返回正常 IP”的证据，需等待完整 UDP／TCP 应答。此修改不把超时或 SERVFAIL 补算为拦截，也不改变历史周期。

统计保存在 `/tmp/adzero-observe/` 的小份内存文件中。同次开机重启统计服务、规则更新和暂停恢复不会主动清零累计数；重启路由器后清零。关闭保护时停止采集。页面每秒读取小份快照，不下载规则、不扫描规则列表、不获取全部查询日志，也不重载 DNS 或代理。

采集器异常或尚未就绪时显示「—」，不会用「0」冒充已经确认没有拦截。

`available: true` 只表示采集组件在运行，`active: true` 才表示当前正在计数。过滤已开启、统计尚未就绪时，页面会显示具体原因；如果已有累计数，会保留数字并标明当前统计已暂停。

## 检测当前电脑

1. 开启保护，等待统计就绪，然后点击「开始检测」。
2. 在连接此路由器的电脑上打开终端，复制并执行页面给出的三条 `nslookup` 命令。
3. 保持页面打开，看到设备标记、拦截样本和正常解析三个步骤完成后，显示「此设备检测通过」。

首条命令使用随机的 `.adzero.invalid` 标记。该域名不存在，出现“找不到”属正常，其用途是把本次检测与实际发起查询的设备对应起来。

第二条查询当前有效规则确实包含的公开广告域名，第三条查询正常网站。三项必须来自同一客户端、同一 DNS 服务端，并有相应查询与应答；只有查询、超时、SERVFAIL 或来自其他设备的应答均不算通过。检测有效期为两分钟，不需要暂停保护或重载网络。

检测查询从统计数字中排除。规则、DNS 设置、代理接入或运行上下文变化后，需要重新检测；统计异常时不会继续展示为当前已验证。结果只证明本次设备与 DNS 链路符合预期，不能代表所有手机、浏览器和加密 DNS 路径。

## 实现与覆盖范围

DNS 被动观察使用 `tcpdump` 命令与 libpcap、ucode 观察 `network.interface.lan` 的实际接口。后续重建版的依赖改为通用的 **`tcpdump`**，厂商包 `tcpdump-mini` 通过 `PROVIDES:=tcpdump` 同样可以满足依赖；如果已有完整版或 mini，包管理器不必为了 AdZero 强制更换。两者都没有时，由固件正常软件包管理器安装可用提供者，从而保留开箱即用的采样与检测。采集只读取 DNS 包，不修改 DHCP、DNS、防火墙、代理配置或流量去向。缺少标准 `lan` 接口时统计可能不可用，不影响广告过滤。

采集层不依赖特定代理的统计 API，可与 NaiLink、PassWall、OpenClash、Nikki 及无代理路径共同使用，但各固件、接口和代理转发路径仍需真机逐项验证。

当前覆盖 IPv4 / IPv6、UDP / TCP 53 端口的 A / AAAA 查询。支持 Ethernet、VLAN、Linux cooked capture，有限度重组 TCP DNS 帧。重复查询与应答在短期关联窗口内去重；不把未匹配的应答或单纯域名命中计为拦截。

计数需要观察到当前规则命中和拒绝应答：NXDOMAIN、REFUSED、无地址的成功应答或零地址等。它是可观察链路的应答统计，不是各代理内核提供的独立规则命中计数；其他插件或上游过滤同时存在时，不能凭此归因于某一个过滤器。

以下情况不应期待完整计数：

- 终端使用 DoH / DoT、非 53 端口，或绕过该局域网接口。
- 浏览器与终端缓存直接命中，没有发出新的 DNS 请求。
- 其他 VLAN、访客网络、代理内部的加密上游查询。
- 抓包丢失、分片、超长或无法完整重组的 DNS 应答。
- 请求超出关联窗口、跟踪容量上限，或过滤配置尚未确认。

这些情况不会通过猜测补齐数字。故障分析仍需结合终端查询、代理与上游行为。

## 隐私与资源

不保存完整查询日志，不持久化完整抓包，也不把浏览域名或客户端地址发送到云端。请求关联信息只在内存中短暂保留，已通过检测的设备地址保留在本机内存快照中。状态目录权限为 `0700`，文件为 `0600`。

新包依赖于固件可提供的通用 `tcpdump`：原厂完整版和声明提供 `tcpdump` 的 mini 都可以满足依赖，采集模块继续使用 `ucode-mod-uloop` 等常规依赖。隔离测试仍采用官方 `tcpdump-mini` 作为测试夹具，不要求覆盖路由器原有的完整版。**注意：公开 v0.21.5 安装包仍使用旧的强制 mini 依赖，此修复只适用于以后重新编译发行的包。**

统计进程独立于控制器的操作锁。规则不变时复用已加载的匹配表；配置或代理上下文变化只更新检测上下文，规则文件改变时才重新载入规则。规则匹配、请求关联、TCP 缓冲均有容量限制。

v0.12.2 修复恢复记录中状态字段位于大段规则数据后面时，统计被错误关闭的问题。完整解析顶层状态字段，按文件身份缓存少量状态信息；文件没有变化时不重复读取或解析。仅接受当前服务用户拥有的私有常规文件，最大 64 MiB，不输出记录内容，不调用代理 API 或重载服务。

## 计数暂时不变怎么判断

请求总量增长、拦截量不变，并不一定是统计失效。只有新发出的 A / AAAA 查询命中当前规则，并收到可观察的拦截应答，才会增加拦截量。普通网站、缓存命中或返回真实地址的匹配查询都不能算作拦截。

v0.13.0 增加当前接入期间的诊断计数（`current`）：`matched` 是规则命中的查询数，`matched_answered` 是收到应答的命中数，`matched_positive` 是其中仍返回正常 IP 的数量。后者出现时页面会提示通过“效果检测”核对链路，不能仅凭代理名和规则已同步认定实际生效。超时、SERVFAIL 和没有观察到的应答仍不算拦截。

“当前接入”与规则数量通过同一份轻量快照同步，后台切换完成后无需重新打开页面；不会每秒完整探测代理或重载网络。累计数保留本次开机历史，`current` 随接入或规则上下文变化清零，避免把上一条链路的问题算在新代理上。

## 临时查看最近拦截

点击“查看最近拦截”后，接下来 5 分钟最多显示 30 个域名。重复域名合并计数，仅列出确实收到拦截应答的记录；终端效果检测流量排除在外。

记录仅在内存中保留，不含设备地址，不上传。停止、到期、规则或接入上下文变化后清空；重启不恢复域名历史。关闭页面后仍会记录到原定到期时间，也可返回点击“停止并清空”。

点击“检查并放行”会先查询当前有效规则并展示匹配范围，再由用户确认是否放行，不会自动放行整个父域名。启停临时记录无需重载 DNS、代理或规则。
