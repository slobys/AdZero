# 桥接 LAN 切换代理后的 DNS 统计

## 已确认的两个问题

2026-11-01 对用户 OpenWrt 路由器进行了只读检查。AdZero 0.23.4 已识别 NaiLink / mihomo，规则后端就绪，采集进程存活且每秒更新快照；不能因此认定请求链路完整。

1. 主网桥抓包只看到客户端应答。原始请求在桥成员上仍是 53 端口，到达主网桥时已被代理 NAT 重定向至内部 DNS 端口，原采集过滤器遗漏了请求。没有请求关联的应答不能计数。
2. 分段查询观察到 NaiLink 本地 DNS 桥对规则样本返回 REFUSED，而 mihomo 面向客户端返回 SERVFAIL。其他采样窗口也出现过客户端直接收到 REFUSED 的情况。不能把所有失败一概当作广告拦截，更不能凭当前状态追溯所有历史查询。

## AdZero 的修复范围

- 桥接 LAN 从主网桥和当前成员接口采集原始 53 端口 DNS，使用内核接口索引限定范围；非桥接口保留原路径。
- 继续使用请求、应答、五元组、查询 ID 和域名关联及去重。只收到应答、只有规则命中、重复包和超时均不会虚增拦截数。
- 新增命中规则但收到 SERVFAIL 的独立诊断计数与提示；不加入已拦截、最近拦截或效果检测成功凭据。
- 不修改 NAT、上游、缓存、代理内核、用户规则或恢复记录。不扩大到 WAN、其他网桥和终端加密 DNS。

## 验证与边界

- 原生 OpenWrt ucode：38 项统计回归，包括 cooked capture、桥接重复视图、重定向请求、SERVFAIL 分类、清零及旧计数保留。
- LuCI：426 条 UI 回归断言，核对 IP 正应答与 SERVFAIL 两类提示可以同时显示。
- 隔离网络／挂载命名空间：真实网桥、veth、独立客户端、nft DNAT、官方 tcpdump-mini / ucode / dnsmasq。UDP/TCP 共 4 次查询及应答，正确记录 2 次拦截；重复视图只计一次，无关 WAN 接口上的查询不计入。
- 真机只读对照：从用户电脑直接发出两条公开广告样本和一条正常域名的 UDP/TCP 查询，共 6 次。旧生产采集器在窗口内未增加计数，候选解码器关联 6 条查询和 6 条应答；4 条广告样本依实际应答分别归入拒绝或 SERVFAIL，不猜测补齐。

真机验证只对本次探测的独立源端口做短时内存抓包，没有保存完整抓包、修改配置、安装候选包或重启服务。以上不是所有固件、VLAN、无线桥、TUN、IPv6 及完整网页可用性的认证。NaiLink / mihomo 拒绝应答转为 SERVFAIL 的行为仍须由其 DNS 桥／解析层修复；AdZero 的统计改动不会修复该行为。
